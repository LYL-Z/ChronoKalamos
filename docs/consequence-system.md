# 阶段 10：后果系统

## 事件目录

内容版本为 `10.0.0`。当前机械基线包含9个事件。三个出身各有3个连续事件。每个事件有3个选择，共27个编辑者定义的后果。

这不是阶段 11 的内容规模验收。它只证明机制闭环。人物数量、事件密度、章节长度和外部史学审阅仍属于后续内容工作。

每个 `EventTemplate` 固定：

- 场景、章节与允许出身；
- 回合、地点和状态前置条件；
- 3—5个选择；
- 每个选择的 `consequenceKey`；
- 有限 `StateDelta`；
- 关系记忆与风险时钟变化；
- 下一事件或章节结局；
- 证据编号与发布状态。

## 确定性提交

客户端只提交选择 ID 或自由文本。服务端先把输入解析到当前事件的一个选择。后果由事件目录查得，模型不参与这一决定。

数据库提交前再次核对：

1. 会话属于当前用户。
2. `world_state.story.currentEventId` 与提交事件一致。
3. 事件处于 `published`。
4. 出身满足事件范围。
5. 选择 ID 与 `consequenceKey` 是同一注册记录。
6. 下一事件或结局与注册表一致。
7. 已完成事件和最后一条决定已经写入候选状态。
8. 叙事来源属于事件证据范围。

任何一项失败都会回滚整个事务。

## 关系记忆与风险时钟

关系记忆保存 `relationshipId`、事件、摘要、倾向和回合号。它不是模型自由编写的长期记忆。文本来自事件模板。

风险时钟保存进度、阈值和状态。进度达到阈值时标为 `triggered`。明确解决时标为 `resolved`。模型只能在叙事中描述已经计算出的风险，不能改变进度。

## 章节结局与重玩

结局是后果的一部分。它固定标题、摘要、证据标签和来源。结局提交时，事务同时生成 `game_replay_summaries`。

重玩不会删除旧存档。浏览器为同一出身生成新的 `client_session_id`，旧会话继续留在历史存档中。回顾包含决定、关系变化、未解风险、结局和下一入口。

## 旧存档迁移

零到两回合的旧存档可映射到新事件序列。三回合以上的旧存档缺少可证明的事件—选择—后果链。迁移将其标为 `legacy-session-boundary` 并结束旧章。该处理保留状态，但不伪造既往决定。
