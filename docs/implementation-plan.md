## 实测证据

`npm run test:supabase:live` 使用 `.env.test` 中的两个 publishable 配置执行了真实请求。测试验证了：

1. 两个匿名用户都能建立自己的 `profiles` 和 `game_sessions`。
2. 重复 `client_session_id` 不会覆盖第一次存档。
3. 用户 B 无法读取、更新或删除用户 A 的存档和上传元数据。
4. 用户 B 无法下载或写入用户 A 的私有对象路径。
5. 用户 A 能读取自己的对象。
6. 游客升级后保留原用户 UUID，并在重新用邮箱密码登录后仍能读取原存档。

升级连续性测试在测试项目中临时关闭邮箱确认，测试结束后已恢复开启。因此该证据不等同于“邮件已投递并完成点击确认”。正式邮箱升级仍要求可用的邮件发送配置和真实收件箱验收。

生产站版本 9 已在 Chrome 登录态下复核。390px 与 768px 均无横向溢出，游客会话和存档刷新后仍可恢复。复核中发现的 5 个小于 24px 的按钮目标已修复。截图与审计记录位于 `audit/phase3-production/`。

`npm run test:supabase:live` 在 `.env.test` 不存在或缺少两个变量时会跳过。跳过不等于通过。
