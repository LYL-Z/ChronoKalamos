# 阶段3身份流程

## 游客开始

1. 浏览器调用 Supabase 匿名登录。
2. Supabase 创建真实 `auth.users` 记录和可刷新的浏览器会话。
3. `handle_new_user` 触发器创建同 ID 的 `profiles` 记录。
4. 前端只用 publishable key。数据库权限由 RLS 决定。

游客并非“无身份”。它是无法通过邮箱重新找回的匿名用户。退出登录、清除浏览器数据或换设备后，旧凭证无法恢复。界面必须在建立游客身份之前展示这项风险。

## 邮箱登录与升级

未登录用户使用邮箱 OTP 链接。匿名用户使用 `updateUser({ email })` 绑定邮箱。Supabase 项目必须开启匿名登录和手动身份关联，并正确配置站点 URL、重定向 URL 与邮件发送能力。

匿名升级保留原用户 ID，因此已有 `owner_id` 无需修改。如果邮箱已经属于另一个账户，应用不得自动合并两个用户。自动合并会引入账户接管和跨用户数据误归属风险。该情形应要求用户登录已有账户，并在后续设计明确的、可审计的迁移流程。

## 未启用入口

微信、QQ 和手机号仍显示“筹备中”。阶段3没有相应供应商、审核资质、反滥用策略或账号恢复策略，因此不得显示可点击的伪登录按钮。
