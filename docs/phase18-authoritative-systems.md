# Phase 18 权威玩法事务

## 边界

本阶段把五段核心循环写入同一个权威 `WorldState`：

```text
家户关系 → 官职公务 → 物品交易 → 高门网络 → 全国治理
```

这里的婚姻、官职、高门和全国治理均为 742 年长安背景下的叙事模拟。它们不声称复原真实个人履历，也不改变唐玄宗时期的已知历史。子女系统只记录未成年人的照护关系，不推断血缘、生育能力或价值。

## 事务合同

每个动作包含 `clientActionId`、预期状态版本、动作、后果取向和严格参数。应用规则引擎只能生成候选状态。生产数据库随后执行以下步骤：

1. 以 `owner_id + client_action_id` 检查幂等重放。
2. 锁定当前用户的 `game_sessions` 行。
3. 检查状态版本、动作范围、时间推进和不可变字段。
4. 检查婚姻同意、案卷证据、官职前置、高门前置和治理前置。
5. 检查事件来源均为已发布来源。
6. 在同一事务内写入动作账本、会话状态和检查点。

浏览器只能读取自己的动作账本。浏览器不能直接插入、更新或删除账本，也不能执行写入 RPC。服务端只能读取账本并执行 `server_commit_system_action`。

## 关键链

| 领域 | 权威动作 | 主要守卫 |
|---|---|---|
| 家户 | 年龄确认、照护、婚约、子女照护 | 双方成年、明确同意、家户声望、照护容量 |
| 案卷 | 立案、核验、结案 | 先研习制度、单一活动案卷、至少一项证据 |
| 官职 | 架空试任、履行公务 | 两次研习、一宗结案、已取得试任 |
| 交易 | 买入、卖出、工坊生产 | 目录物品、余额、持有状态 |
| 高门 | 引见、议事 | 家户声望、公务、交易三项前置 |
| 治理 | 架空治理入口、财赋、赈济 | 已进入高门议事、国库、有效道级区域 |

## 50 个结局

`buildPhase18ReachabilityPlan` 为 10 组、每组 5 个结局生成可执行动作序列。测试从三个出身的标准初始状态执行规则，不靠静态布尔值或测试特权。结局必须满足所属组前置和五种后果取向之一，最后由 `conclude-chapter` 写入 `story.chapterEnding` 与 `systems.activeEndingId`。

这证明规则图可达，不证明 50 个结局已经获得历史学者审阅。所有结局仍按 `叙事虚构` 处理。

## 公共入口

- `POST /api/game-sessions/:id/system-actions`
- `game_system_actions`：不可变动作账本
- `server_commit_system_action`：仅 `service_role` 可执行
- `WorldState.systems`：规则版本 `18.0.0`

请求体上限为 12 KiB。读取过程同时限制声明长度和流式实际长度，避免分块请求绕过限制。
