# Phase 17 章程：天下与制度玩法地基

## 结论

Phase 17 先补齐高密度玩法入口，再进入大规模事件生产。它不把菜单数量当成玩法完成度。当前三种出身的回合事务仍是唯一权威写入路径。新增的阶层、地图、朝政、内廷、家户、物品和结局都必须服从现有叙事契约与后果系统。

## 权威边界

```text
工作台动作
→ 只写入自由行动草案
→ 当前 EventTemplate 解释为允许选项
→ 规则引擎计算 StateDelta
→ Zod 校验
→ 数据库事务提交
```

工作台、DeepSeek 和客户端都不能直接修改世界状态。高阶玩法要成为完整可玩系统，仍需：

1. 扩展 `WorldState`，加入官职、家户成员、婚姻、子女、机构案卷和全国治理字段。
2. 为每个字段定义 Zod、迁移、RLS、幂等 RPC 和回滚策略。
3. 制作编辑事件。每个动作要有前置条件、费用、后果、失败结果和来源。
4. 为 50 个结局建立可达性测试。不可达条目不能发布。
5. 外部历史审阅完成前，新增条目保持 `provisional`。

## 产品安全

- 公开产品保持 16+。
- 婚姻、生育和亲密关系玩法只对 18 岁以上角色开放。
- 明确同意是硬条件。胁迫可作为风险被处理，但不能成为奖励机制。
- 不设置“生育能力值”或“宠幸值”。
- 不用子女数量衡量角色价值。
- 内廷重点是制度、供给、健康、礼仪与申诉。

## 进入下一生产批次的条件

1. 当前 Phase 17 注册表、UI、响应式、键盘与 axe 验收通过。
2. 为官职、家户与国家治理提交独立 ADR 和迁移设计。
3. 先制作每层 3 个可达事件，不批量铺开全部结局。
4. 事件可达性、状态不变量和跨用户隔离测试通过。
5. 外部审阅者身份与签字证据可核后，才可把对应史实内容从 `provisional` 升级。
