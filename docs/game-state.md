# 阶段 5：游戏状态与事务边界

阶段 5 把“世界状态”从界面文案提升为可验证的领域对象。阶段 10 又收紧了权限：`StateDelta` 只能来自发布的事件模板。模型不能提出或修改状态变化。

## 状态结构

`WorldState` 固定包含：

- 时间：742 年、季节、叙事日序、日内分钟、累计分钟、回合号。
- 地点：稳定的地点 ID 与读者可见名称。
- 健康：`vitality` 0–10、状态和死亡记录。
- 身份与职业：三种出身模板之一，以及当前职业。
- 记账单位：非历史价格表的游戏记账单位“文”，所有变化受每回合边界限制。
- 物品、关系、声誉、技能、任务和风险。

时间从天宝元年春季的叙事起点开始。日序用于游戏节奏，不宣称某一条未经证实的公历日期。742 年按儒略历不是闰年，因此规则引擎把单场景上限固定为 365 天。

## 单回合流程

```text
玩家文字 / 选项
→ Supabase RPC 预留 clientTurnId
→ 内容审核
→ 已发布历史主张与来源检索
→ 当前事件、身份、地点、时间与前置条件检查
→ 规则引擎选择编辑者定义的 Consequence 与 StateDelta
→ DeepSeek 仅生成叙事表达、允许选项的改写和来源编号
→ Zod、来源集合与选项集合校验
→ 服务端专用 Supabase RPC 原子提交 game_turn + session + checkpoint
```

模型不能调用数据库，不能返回 `StateDelta`，也不能返回完整世界状态。事务函数只接受服务端规则计算出的下一状态，并再次核对事件、选择、后果键、下一事件、来源和章节结局。

阶段 10 在 `WorldState.story` 中加入章节、当前事件、已完成事件、决定摘要、关系记忆、风险时钟和章节结局。旧版三回合以上存档无法可靠重建其因果链，因此迁移会写入明确的旧版存档边界，不伪造历史决定。

## 幂等与失败

`game_turn_requests` 用 `(owner_id, client_turn_id)` 唯一键和输入哈希保存预留状态。相同请求只会：

- 回放已提交结果；
- 告知另一请求仍在处理；
- 回放同一失败结果。

规则失败、审核拦截、模型拒答、超时和第二次结构校验失败都会写入失败状态，但不会更新 `game_sessions.world_state`。
